UX concept

Multi-select Events in Google Calendar

Google Calendar forces users to move events one by one — unnecessary friction when an unexpected day off throws an entire week into disarray.

Personal concept, not affiliated with Google. A UX reflection based on real usage and public information. No validation or collaboration from Google.

Product
Google Calendar (web)
Type
Personal concept
Tools
[Figma / to be completed]

The user problem

In Google Calendar's week or month view, clicking and dragging on the grid creates a new event — it never selects existing ones. There is no way to select multiple existing events to move, delete or reschedule them together.

In practice: an unexpected day off means opening and moving every event individually. For a busy day (5–8 slots), that's 5–10 minutes of repetitive clicks — and a real risk of forgetting something or dropping it in the wrong place.

[Annotated screenshot: current drag gesture → creates new event instead of selecting existing ones]

My hypothesis

If Google Calendar offered a multi-select mode — similar to a file manager — users could move, reschedule or delete several events in a single action, significantly reducing the time and errors involved in replanning an unexpected change.

The proposal

A "Select" button in the toolbar (or keyboard shortcut S) activates a selection mode, distinct from the default creation mode. Behaviour changes as follows:

  • Clicking an event checks it (without opening it).
  • Click-dragging on the grid selects all events within the drawn range.
  • Shift+click extends the selection to an additional event.
  • Once a selection is made, a contextual menu offers: Move to…, Postpone by X days, Delete.
  • A visible indicator (banner or counter) shows that selection mode is active, with a "Cancel" button to exit.
[Mockup: week view with 3 checked events + floating contextual menu — "Move to…" / "Postpone 7 days" / "Delete"]

How to measure success

  • Average time to reschedule 5 or more events (target: reduce by 3×).
  • Adoption rate of selection mode in planning sessions.
  • Reduction in reported errors (missed event, dropped in wrong slot).
  • Satisfaction score on unexpected change management (NPS or targeted CSAT).

Limits and next steps

This concept doesn't resolve everything: the behaviour for recurring events (move one occurrence or the entire series?) still needs definition. Shared calendar permissions also add complexity. On mobile, the selection gesture needs rethinking to avoid conflicting with scrolling.

Natural next steps: user testing on the prototype (5 participants, "last-minute change" scenario), then iteration on how selection mode is triggered (button vs shortcut vs long press).
